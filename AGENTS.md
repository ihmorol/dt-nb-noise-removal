# Working in this repository (for AI agents and new contributors)

This repository's value is that every number is honest, pre-registered, and reproducible.
The rules below are how that is preserved. Read them before changing anything.

## Read first, in this order

1. `README.md` — what the project is and how to run it.
2. `CONTEXT.md` — the fixed domain vocabulary. Use these exact terms (Alg 1, Alg 2, judge,
   support, Path 1/2, Protocol A/B/C, R1 world vs pipeline world).
3. `DECISIONS.md` — the append-only decision log. Every experiment's design was written here
   *before* its results existed.
4. `trackers/experiments.md` — the registry: one row per experiment, append never delete.

## Hard rules

- **Pre-register before results.** Starting a new experiment? First append a `DECISIONS.md`
  entry with the design, the exact choices (judges, thresholds, formulas), and the success
  criteria. Never pick a knob after seeing outcomes; if a mechanics fix is forced mid-run
  (e.g. a timeout), document it and note that it was chosen before analysis.
- **One experiment = one script.** A script in `code/` that writes everything to
  `results/EXP-<id>_<shortname>/` (a `config.json` plus CSVs). If it is not reproducible from a
  committed script, it does not count as a result.
- **Honest protocol for headline numbers.** Everything refit inside each training fold
  (protocol B). Protocol A (fit before CV) exists only to quantify leakage — never mix them
  silently, never report A as a performance estimate.
- **Shared folds only.** `pipeline.make_folds(y, seed)` is the single fold source; arms compared
  with each other must run on the same folds (paired comparisons and determinism anchors depend
  on it).
- **Verify before trusting.** `python verify_faithful.py` and `python check_pipeline.py` must
  ALL PASS after any change to shared code (`data.py`, `faithful_nb.py`, `weka_utils.py`,
  `pipeline.py`). When changing a model class, keep the old unweighted code path bit-identical.
- **Environment pins.** `pandas<3` is load-bearing (`code/data.py` detects nominal columns via
  `dtype == object`; pandas 3 breaks it). Java 17+ with the vendored jars in `code/lib/` for all
  Weka-based scripts.
- **No hand-typed numbers in papers.** Tables are generated by `paper/*/scripts/make_*.py` from
  the results CSVs; regenerate them after every new run.
- **Close the loop.** After every experiment: update its registry row (results + verdict),
  refresh the stale-docs if they mislead, and commit before and after the run.

## Environment for a fresh clone

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
java -version   # 17+, jars vendored in code/lib/
```

Runtime expectations: `e9_farid.py` and `e5_strategy.py` are hours-long at 10 seeds (JVM per
fold; NSL-KDD last and heaviest) and write results incrementally per dataset; everything else is
minutes. Weka's Logistic is unusable on NSL-KDD's unscaled features (timeouts) — the third judge
is sklearn's standardized `LogisticRegression` (see `DECISIONS.md`).

## Commit style

Conventional-commits-like, one logical unit per commit:
`experiment(e5): graded noise handling beats hard deletion`, `docs: ...`, `fix(pipeline): ...`.
Include the headline result in the body, plus a Tested: line naming the verification scripts run.
